System Architecture & Methodology

A comprehensive overview of the machine learning pipeline, geospatial engineering, and deployment strategies powering the NYC Taxi Predictor.

🧠 Machine Learning Approach

The core prediction engine is built upon an optimized LightGBM Regressor. Selected for its exceptional training speed and low memory footprint in production environments, the model was trained on historical Kaggle competition data encompassing millions of New York City taxi trips.

Extensive hyperparameter tuning was conducted to manage the extrapolation constraints inherent in tree-based algorithms. The feature engineering pipeline extracts nuanced temporal patterns (day of the week, hour of the day) and transforms raw geographic coordinates into physical Haversine distances to maximize predictive accuracy.

🗺️ Geospatial Engineering

To bridge the gap between mathematical model requirements and human-centric design, the frontend utilizes advanced geospatial APIs. Leaflet.js and CartoDB provide the minimalist map visualization.

User inputs are dynamically parsed using the Nominatim OpenStreetMap API for reverse and forward geocoding, converting clicked locations or text inputs into precise coordinates. Finally, the OSRM (Open Source Routing Machine) calculates real-time road routing, snapping the trip path to actual NYC streets rather than relying on geometric straight lines.

⚙️ Modular MLOps Pipeline

The backend architecture follows strict MLOps principles, utilizing a modular Python structure. Dedicated components for data ingestion, data transformation, and model training ensure the system is highly scalable and easily retrainable as new data becomes available.

The application is served via a Flask API. To eliminate disk-read latency during user requests, the predictive model and data preprocessors are cached globally in memory upon server initialization, resulting in millisecond prediction response times.
